## Admin account namespace — OWNER LOCK

The owner explicitly confirmed that `Danh sách Admin` is specialized and independent from employee/master catalogs.

### Fixed allowed Admin positions

`Danh sách Admin_Vị trí` is fixed system-wide to exactly:

- `superadmin`
- `admin`
- `user`

No other value is valid.

### Mandatory interpretation

- Never source Admin `Vị trí` from `Danh mục`.
- Never fall back to `DANH SÁCH NHÂN SỰ_Vị trí chính`.
- Never copy employee job titles (`Chuyên viên`, `Điều phối`, `Trưởng nhóm`, etc.) into Admin `Vị trí`.
- Similar field names in different sheets remain separate namespaces unless the owner explicitly maps them.
- Android/GAS must derive or validate Admin position from the Admin role rather than trusting arbitrary client input.
- Normal app account creation does not create a new `SUPERADMIN`; changing that capability requires explicit owner approval.
- The allowed set `superadmin/admin/user` may only be changed after a new explicit owner instruction.

## Verified state at this checkpoint

- `Danh sách Admin` sheet positions were normalized to the fixed role-aligned values.
- Android account creation uses a fixed Admin role/position selector rather than employee catalog values.
- GAS account upsert derives Admin position from role and rejects roles outside the allowed normal creation path.
- The rule is also recorded in `docs/ADMIN_ACCOUNT_RULES.md` and `AGENTS.md`.
