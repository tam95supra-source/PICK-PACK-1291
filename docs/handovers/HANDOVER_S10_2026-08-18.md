## 5. Core business invariants

- `MNV` is the business key.
- Session key: `MNV + business_date`.
- State machine: `NOT_ENTERED → ACTIVE → ENDED`.
- Once ENDED, normal flow cannot re-enter the same business date.
- Mutations use immutable/idempotent `event_id`.
- Exclusive resources are race-safe with exactly one winner.
- Resource changes are atomic; failure retains the previous resource.
- Operational session/resource state remains server/Sheet authoritative.

## 6. Authentication, roles and session

Roles:

- SUPERADMIN
- ADMIN
- USER

Backend enforcement is mandatory; hidden UI alone is not authorization.

Credential model:

- salted PBKDF2-HMAC-SHA256 verifier
- challenge/HMAC login proof
- plaintext password is not sent directly to GAS
- no passwords/verifiers/private tokens/signing private material in public repo/handover

Session model: **`SINGLE_ACTIVE_DEVICE_V1`**.

- Session survives normal app/process closure on the same installation.
- No routine 12-hour forced logout.
- Login on another installation replaces the same account's active server session.
- Old device is rejected on the next protected API/sync opportunity.
- Logout/password reset/security changes may invalidate the session.

Forgot-password flow remains account-Mail based, generic externally, rate-limited, and invalidates the previous active session when reset succeeds.

## 15. Known risks / technical debt

- S10/S11 UI changes are applied through assertion-based build-time source transforms (`tools/apply_s10_ui_patch.py` followed by `tools/apply_s11_compact_report_patch.py`). This is controlled and currently passes CI, but anchors can become fragile if the base Kotlin changes. Future edits must preserve unique anchors or deliberately fold the patch into source in a controlled change.
- Report composition now combines multiple API calls. Validate behavior on slow/unstable PDA networks and confirm no stale mixed-snapshot presentation becomes confusing.
- `list_labor` is permission-restricted; detailed deducted-support composition is therefore an admin-capability path. Do not weaken backend authorization merely to make the report visible to unauthorized roles.
- Beta11 has CI/OTA verification but still needs owner real-device visual/business acceptance.

## 16. Known failures not to repeat

- Do not assume `./gradlew`; use setup-gradle + `gradle`.
- Do not embed giant multiline Kotlin/Python source patches inside workflow YAML.
- Use coherent standalone transform scripts/direct edits with unique asserted anchors.
- Fix the first/root compile error, not cascades.
- Do not create per-release observer/status/finalizer workflows.
- Do not let CI self-edit workflow definitions.
- Do not hardcode stale Beta versions.
- Do not run full release/live gates for small non-release edits.
- Do not regenerate signing identity.
- Do not return to manual recovery-signing while the four GitHub signing secrets are healthy.
